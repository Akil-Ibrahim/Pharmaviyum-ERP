# Оценка качества фармацевтического RAG

[English](ragas-pharmaceutical-evaluation.md) · **Русский**

## Назначение и границы применения

В Pharmaviyum для production-оркестрации RAG используется LangGraph. Ragas является **зависимостью для offline-оценки**, а не частью production request path. Устанавливайте его только в среде оценки:

```bash
uv run --with-requirements requirements-eval.txt python -m pytest tests/unit/ai/test_ragas_evaluation.py
```

Адаптер ориентирован на Ragas Collections API версии 0.4. LLM-оценщик и embeddings передаются явно; production credentials провайдера не считываются автоматически.

Метрики Ragas — вероятностные измерения с помощью LLM-as-a-judge. Это регрессионные сигналы, а не клиническая валидация, регуляторная сертификация или доказательство безопасности.

## Стандартные метрики Ragas

- **Faithfulness** — доля утверждений ответа, подтверждённых найденным контекстом.
- **Answer relevancy** — косинусное сходство между запросом и вопросами, выведенными из ответа. Допустимый диапазон — `[-1, 1]`; отрицательные значения допустимы, их нельзя автоматически ограничивать нулём или отклонять.
- **Faithfulness, context precision и context recall** — нормализованные показатели в диапазоне `[0, 1]`.
- **Context precision** — насколько релевантные чанки находятся выше нерелевантного шума в выдаче.
- **Context recall** — насколько найденный контекст покрывает эталонный ответ.

Для context precision и context recall нужен подготовленный эталонный ответ. Если эталонных данных нет, результат помечается как недоступный, а не молча заменяется нулём.

## Фармацевтические метрики

| Метрика | Контракт оценки |
|---|---|
| Корректность цитирования | Каждое фактическое утверждение содержит реальный citation ID; независимый entailment-оценщик подтверждает, что указанный источник действительно поддерживает утверждение. |
| Точность лекарственных сущностей | Точные precision/recall/F1 для названия препарата, дозировки/концентрации и лекарственной формы. |
| Сохранение отрицаний | Размеченные положения сохраняют ожидаемую положительную/отрицательную полярность. |
| Частота клинических галлюцинаций | Количество неподтверждённых клинических утверждений, делённое на общее число размеченных клинических утверждений; меньше — лучше. |
| Изоляция контекста пациента | Закрытые источники должны соответствовать аутентифицированной аптеке и, для записей пациента, выбранному пациенту. Любое несовпадение — ошибка. |
| Мультиязычный retrieval | Recall эталонных источников измеряется отдельно для русского (ru) и английского (en). |

Для корректности цитирования и частоты клинических галлюцинаций требуется явно переданный claim-support judge. Если оценщик не настроен, результат считается **недоступным**: синтаксически корректная ссылка не доказывает логическую поддержку утверждения источником.

Метрики лекарственных сущностей и отрицаний требуют структурированных эталонных меток или независимо извлечённых предсказаний. Нельзя получать ground truth из того же ответа модели, который оценивается.

Изоляция контекста пациента — детерминированная проверка авторизации. Её необходимо тестировать на границе retriever/БД с фиктивными записями других аптек и пациентов. Не используйте реальные данные пациентов в golden dataset.

## Требования к датасету

Поддерживайте версионируемые эталонные наборы синтетических или обезличенных кейсов со следующими данными:

- метки языка и юрисдикции;
- эталонный ответ и gold source/chunk IDs;
- метки названия препарата, дозировки и лекарственной формы;
- метки отрицаний на уровне отдельных утверждений;
- клинические утверждения и метки подтверждающих доказательств;
- метки аптечной/пациентской области доступа для синтетических тестов изоляции.

Балансируйте русские и английские кейсы и публикуйте оценки отдельно по каждому языку. Не объединяйте оба языка в одну метрику, которая может скрыть низкое качество на одном из них.

## Release gates

Используйте два независимых этапа проверки:

1. **Быстрый детерминированный CI:** лекарственные сущности, отрицания, изоляция пациента, recall gold sources, валидность citation ID и схема датасета.
2. **Плановая/запускаемая вручную LLM-оценка:** метрики Ragas, entailment цитат и поддержка клинических утверждений.

Критические ошибки нельзя компенсировать средним баллом: нарушение области доступа пациента, неверная дозировка/форма препарата, потерянное отрицание или неподтверждённое клиническое утверждение высокого риска блокируют продвижение, даже если агрегированные показатели Ragas высоки. Пороговые значения нужно калибровать на наборе, проверенном фармацевтом, прежде чем использовать как production release criteria.

## Конфиденциальность

Датасеты оценки не должны содержать идентифицируемые данные пациентов. Не передавайте идентификаторы пациентов, текст рецептов, prompts, найденные записи пациентов или PHI сторонним judge-моделям. Храните агрегированные оценки и обезличенные ID кейсов; подробные артефакты оценки должны быть защищены контролем доступа и политикой хранения.
