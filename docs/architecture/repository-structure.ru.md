# Структура репозитория

[English](repository-structure.md) · **Русский**

Этот документ описывает текущую структуру репозитория и правила размещения новых файлов. Он носит описательный характер: перенос каталогов выполняется отдельно, с одновременным обновлением всех ссылок в CI, Docker, конфигурации развёртывания, инструментах и документации.

## Код приложения

| Путь | Назначение | Правило |
|---|---|---|
| `src/pharmaviyum/` | Python-пакет приложения: API, доменная логика, слой хранения данных, интеграции и Mortarium AI | В этом каталоге размещается production-код Python. Не создавайте параллельный пакет верхнего уровня `backend/`. |
| `frontend/shadcn-admin/` | Административный интерфейс на React, TypeScript, Vite и shadcn/ui | Зависимости, исходный код и lock-файлы frontend должны находиться в каталоге этого приложения. |
| `alembic/` и `alembic.ini` | Миграции схемы базы данных | Историю миграций следует считать неизменяемой; новые ревизии создаются средствами Alembic. |
| `tests/` | Автоматические backend-тесты и межслойные тесты | Организуйте тесты по области и домену; не дублируйте здесь код приложения. |

## Инфраструктура и поставка

| Путь | Назначение |
|---|---|
| `.github/workflows/` | CI, проверки безопасности и явно управляемые процессы развёртывания |
| `ansible/` | Автоматизация инфраструктуры Pharmacy Edge, inventory-файлы, роли и playbook |
| `docker/` | Ресурсы Docker: образы и конфигурация контейнеров |
| `deploy/` | Ресурсы развёртывания, не относящиеся непосредственно к пакету приложения |
| `nginx/` | Конфигурация reverse proxy Nginx для корневой Compose-топологии |
| `docker-compose.yml` | Локальная/основная топология Docker Compose |
| `docker-compose.codespaces.yml` | Переопределения для GitHub Codespaces |
| `docker-compose.monitoring.yml` | Стек мониторинга |
| `docker-compose.prod.yml` | Compose-конфигурация Production/Edge; перед использованием требуется проверка. Не следует считать её способом развёртывания FastAPI Cloud |
| `Dockerfile` | Сборка образа приложения |
| `scripts/start.sh` | Точка входа запуска контейнера и выполнения миграций |

FastAPI Cloud является отдельной целевой production-платформой. Не рассматривайте корневые Compose-файлы как конфигурацию её развёртывания. Не объединяйте настройки FastAPI Cloud, Pharmacy Edge, локальной разработки и мониторинга в один неоднозначный Compose-файл.

## Конфигурация в корне репозитория

В корне следует размещать только общие точки входа репозитория и стандартные конфигурационные файлы инструментов: `pyproject.toml`, `uv.lock`, `pytest.ini`, `alembic.ini`, `Makefile`, `Dockerfile`, `README.md`, `AGENTS.md`, а также общие настройки редактора, линтеров и Git ignore.

Конфигурация конкретных инструментов (например, Copilot, Pi, Qwen или agent skills) может оставаться в ожидаемом для инструмента расположении, если этот инструмент действительно поддерживается. Общие инженерные правила должны находиться в `AGENTS.md`; не дублируйте одну и ту же политику в нескольких файлах.

## Правила дальнейшей очистки структуры

1. Не создавайте второй корень приложения, например `backend/`, `app/` или параллельный frontend-пакет.
2. Не добавляйте в Git сгенерированные отчёты покрытия, build-артефакты, кэши, локальные базы данных или секреты.
3. Размещайте runtime-зависимости в соответствующем package manifest и lock-файле; не добавляйте неприкреплённые к версии ad-hoc установки во вспомогательные скрипты.
4. Оставляйте эксплуатационные скрипты в `scripts/`, пока не будет осознанно введена новая структура подкаталогов и обновлены все вызывающие их компоненты.
5. Перед удалением или перемещением файла ищите ссылки на него в YAML-файлах workflow, Dockerfile, Compose, Ansible, Makefile, package scripts, документации и других скриптах.
6. Сохраняйте раздельными скрипты для разных топологий развёртывания, пока эти топологии не будут объединены и протестированы.
7. Не удаляйте исторические свидетельства, миграции или процедуры восстановления только ради сокращения количества файлов.
8. Предпочитайте небольшие PR с аудитом путей и ссылок и проверками CI вместо масштабных перемещений каталогов.
